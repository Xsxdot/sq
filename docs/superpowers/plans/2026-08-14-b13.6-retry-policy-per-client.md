# B13.6 `RetryPolicy` 按客户端类型分别下发 实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 `Settings.BackoffPolicy` 的赋值从 `negotiateSettings` 的公共段拆进发布/订阅两个分支，让订阅端拿到描述 broker 真实重投行为的策略，而不是发布端的 RPC 级重试参数。

**Architecture:** 缺口不在协议（`Settings` 是逐客户端协商的，同一个字段本就可以在两类客户端里取不同值），而在 sq 少分了一次岔。改动只在两处：`internal/core/deliver` 导出一个读现有退避变量的访问器；`internal/rpc/settings.go` 把 `backoffPolicy()` 拆成 `publishBackoffPolicy()`（原样改名，值不变）与 `subscribeBackoffPolicy(group)`（值是 deliver 常量的投影）。发布端行为零变化。

**Tech Stack:** Go；`google.golang.org/protobuf/types/known/durationpb`；被测对象是 `(*rpc.Server).negotiateSettings`，测试走包内（`package rpc`）直接调用，不经 gRPC。

**Spec:** `docs/superpowers/specs/2026-08-14-retry-policy-per-client-design.md`

**基线：** 分支 `feat/auto-renew`（B13 链尾）。**必须从它起**——`internal/rpc/settings.go` 已被 B13.2 与 B13.5 各改过一次，从 `main` 起会冲突。

## Global Constraints

- **不要碰 `settings.go` 里 `fifo` 那段注释。** 它列的三条理由（顺序安全不依赖此标志 / 翻 true 会把重试计数与 DLQ 判定从 broker 夺给客户端 / SDK v5.1.4 内部竞态使翻转不可靠观测）**本条目一条都不消除**。见 spec §4 的订正引注。
- **不要在 `internal/rpc` 里另写 `10s` / `5min` 常量。** 消费端的退避值必须取自 `deliver.RetryBackoffParams()`。同一个事实写两遍、改一处忘一处，正是本条目要消灭的东西。
- **发布端下发值必须逐字段不变**：`Initial=100ms`、`Multiplier=2`、单机档 `Max=1s`/`MaxAttempts=3`、集群档 `Max=3s`/`MaxAttempts=5`。
- 协商是**只读**的：查组用 `meta.GetGroup`（只读），**不得**用 `EnsureGroup`（会建组）。建组由 ReceiveMessage 路径负责。
- 日志用 `s.logger`（`*slog.Logger`），禁止 `fmt.Printf`。
- 不改动 `internal/cluster`、不动 e2e、不引入新依赖。

// TestRetryBackoffParamsMatchesFormula 把导出的三要素钉死在 retryBackoff 的
// 真实公式上。它存在的理由：rpc 层要拿这三个值向消费端描述 broker 的重投
// 行为，一旦访问器与公式漂开，下发的就是一份"看起来对"的假描述，而这种漂移
// 在协议层是观测不到的——只能在这里挡。
func TestRetryBackoffParamsMatchesFormula(t *testing.T) {
	initial, max, mult := RetryBackoffParams()

	// 第 2 次投递即公式的起点（base × 2^0），故 initial 必须等于它
	if got := RetryBackoff(2); got != initial {
		t.Fatalf("initial=%v 与 RetryBackoff(2)=%v 不一致", initial, got)
	}
	// 倍率：第 3 次必须是第 2 次的 mult 倍
	if want, got := time.Duration(float64(initial)*mult), RetryBackoff(3); got != want {
		t.Fatalf("倍率不一致：RetryBackoff(3)=%v，按 mult=%v 应为 %v", got, mult, want)
	}
	// 上限：足够大的投递次数必然落在 max
	if got := RetryBackoff(64); got != max {
		t.Fatalf("max=%v 与 RetryBackoff(64)=%v 不一致", max, got)
	}
}
```

// RetryBackoffParams 返回重投退避的三要素：初值、上限、倍率。
//
// 返回：
//   - initial: 第 2 次投递的不可见时长下限，即公式 base × 2^(n-2) 的起点
//   - max: 退避封顶
//   - multiplier: 倍率，恒为 2（公式里 2^(n-2) 的那个 2）
//
// 用途：协议层（internal/rpc）把 broker 的真实重投行为投影成下发给消费端的
// RetryPolicy。它与 RetryBackoff 读同一组变量，两者永远不会漂开——这正是
// 本访问器存在的意义，调用方不得自己另写一套 10s / 5min 常量。
//
// 返回 float64 而不是协议层要的 float32：本包不认识 protobuf 类型，转换由
// 调用方显式做。
func RetryBackoffParams() (initial, max time.Duration, multiplier float64) {
	return retryBackoffBase, retryBackoffMax, 2
}
```

// newSettingsServer 造一个只够跑 negotiateSettings 的最小 Server。
//
// 不复用 newTestEnv 的理由：negotiateSettings 只碰 s.cfg / s.mt / s.logger，
// 而 newTestEnv 会起 gRPC 服务与全套引擎，且把 meta 的 defaultMaxAttempts

// 参数：

func newSettingsServer(t *testing.T, defaultMaxAttempts int32, cluster bool) *Server {
	t.Helper()
	st, err := store.Open(t.TempDir(), true, slog.Default())
	if err != nil {
		t.Fatalf("store.Open: %v", err)
	}
	t.Cleanup(func() { st.Close() })
	rep := replication.NewStandalone(st)
	mt, err := meta.New(rep, replication.StandaloneRouter{}, st, true, 4, defaultMaxAttempts, slog.Default())
	if err != nil {
		t.Fatalf("meta.New: %v", err)
	}
	cfg, err := config.Load("")
	if err != nil {
		t.Fatalf("config.Load: %v", err)
	}
	if cluster {
		// 切集群档。判据就是「Cluster 段非 nil」（config.ClusterEnabled() 的
		// 实现即 c.Cluster != nil），所以给一个零值段就够——negotiateSettings
		// 只经 ClusterEnabled() 读它，不碰段内任何字段。
		cfg.Cluster = &config.ClusterConfig{}
	}
	return &Server{cfg: cfg, mt: mt, logger: slog.Default().With("mod", "rpc")}
}

func publishSettings() *pb.Settings {
	ct := pb.ClientType_PRODUCER
	return &pb.Settings{
		ClientType: &ct,
		PubSub:     &pb.Settings_Publishing{Publishing: &pb.Publishing{}},
	}
}

func subscribeSettings(group string) *pb.Settings {
	ct := pb.ClientType_PUSH_CONSUMER
	return &pb.Settings{
		ClientType: &ct,
		PubSub: &pb.Settings_Subscription{Subscription: &pb.Subscription{
			Group: &pb.Resource{Name: group},
		}},
	}
}

func expBackoff(t *testing.T, p *pb.RetryPolicy) *pb.ExponentialBackoff {
	t.Helper()
	if p == nil {
		t.Fatalf("BackoffPolicy 为 nil")
	}
	eb, ok := p.GetStrategy().(*pb.RetryPolicy_ExponentialBackoff)
	if !ok {
		t.Fatalf("策略不是 ExponentialBackoff：%T", p.GetStrategy())
	}
	return eb.ExponentialBackoff
}

func TestNegotiateSettingsPublishBackoffUnchanged(t *testing.T) {
	for _, tc := range []struct {
		name        string
		cluster     bool
		wantMaxMs   int64
		wantAttempt int32
	}{
		{"单机档", false, 1000, 3},
		{"集群档", true, 3000, 5},

		t.Run(tc.name, func(t *testing.T) {
			s := newSettingsServer(t, 16, tc.cluster)
			out := s.negotiateSettings(publishSettings())
			p := out.GetBackoffPolicy()
			if got := p.GetMaxAttempts(); got != tc.wantAttempt {

			}

			if got := eb.GetInitial().AsDuration().Milliseconds(); got != 100 {

			}
			if got := eb.GetMax().AsDuration().Milliseconds(); got != tc.wantMaxMs {
				t.Fatalf("Max=%dms，期望 %dms", got, tc.wantMaxMs)

把 `internal/rpc/settings.go` 里整个 `backoffPolicy` 函数（含其上方注释块）替换为下面两个函数：

```go
// publishBackoffPolicy 下发给**发布端**的重试策略。
//
// SDK 用它做 RPC 级的发送失败重试（producer_options.go 读
// Settings.BackoffPolicy，producer 发送失败时按它退避重发）。按部署形态分档：
//   - 单机档：100ms 起步、每次 ×2、封顶 1s，最多尝试 3 次
//   - 集群档：同上倍率，封顶 3s、最多 5 次——选举窗口实测 1.5s 量级，
//     单机档的 1s×3 次恰好可能全部落在窗口内（见常量注释）
//
// 值与拆分前的 backoffPolicy 逐字段相同：发布端行为不得因本次拆分有任何变化。
func (s *Server) publishBackoffPolicy() *pb.RetryPolicy {
	max, attempts := backoffMax, backoffMaxAttempts
	if s.cfg.ClusterEnabled() {
		max, attempts = backoffMaxCluster, backoffMaxAttemptsCluster
	}
	return &pb.RetryPolicy{
		MaxAttempts: int32(attempts),
		Strategy: &pb.RetryPolicy_ExponentialBackoff{
			ExponentialBackoff: &pb.ExponentialBackoff{
				Initial:    durationpb.New(backoffInitial),
				Max:        durationpb.New(max),
				Multiplier: backoffMultiplier,
			},
		},
	}
}

// subscribeBackoffPolicy 下发给**订阅端**的重试策略。
//
// 与发布端同名字段、完全不同的语义：SDK 用它做消息级处理——
// push_consumer_options.go 读 Settings.BackoffPolicy 存进 pc.retryPolicy，
// nackMessage 用它算重投的不可见时长、eraseFifoMessage 用它判死信。
// 两个用途分属两类客户端，而 Settings 是逐客户端协商的，所以同一个字段本来
// 就可以取不同值——这正是本函数存在的理由。
//
// 参数：
//   - group: 该订阅端的消费组名（可能为空串：客户端未上报组）
//
// 返回：描述 broker 真实重投行为的策略。三个退避要素取自
// deliver.RetryBackoffParams()——**不要在本文件另写 10s / 5min 常量**，
// 那会让同一个事实在两处各写一遍，改一处忘一处。
//
// 注意：本函数只读，不得建组。协商是协议握手，不该有持久化副作用；
// 真正建组由 ReceiveMessage 路径的 EnsureGroup 负责。
func (s *Server) subscribeBackoffPolicy(group string) *pb.RetryPolicy {
	initial, max, mult := deliver.RetryBackoffParams()
	var attempts int32 = meta.DefaultMaxAttempts
	if gc, ok := s.mt.GetGroup(group); ok {
		attempts = gc.EffectiveMaxAttempts()
	} else {
		// 组还没注册（首次连接，还没走到 ReceiveMessage）时下发包默认值。
		// 这条是「为什么这个消费者拿到的是 16 而不是它组里配的值」唯一的
		// 排查线索，故必打；用 Debug 是因为每个消费者首次连接都会命中一次，
		// Info 会把它变成刷屏噪声。
		s.logger.Debug("协商退避策略：消费组尚未注册，回退包默认 maxAttempts",
			"group", group, "max_attempts", attempts)
	}
	return &pb.RetryPolicy{
		MaxAttempts: attempts,
		Strategy: &pb.RetryPolicy_ExponentialBackoff{
			ExponentialBackoff: &pb.ExponentialBackoff{
				Initial: durationpb.New(initial),
				Max:     durationpb.New(max),
				// 协议字段是 float32，deliver 侧返回 float64（本包不认识
				// protobuf 类型），在此显式收窄。
				Multiplier: float32(mult),
			},
		},
	}
}

	// BackoffPolicy 不在公共段赋值：它的语义由客户端类型决定（发布端是 RPC
	// 级发送重试，订阅端是消息级重投与死信判定），放在公共段等于给两类客户端
	// 下发同一份逐字节相同的值，其中必有一份是错的。
	// 客户端未上报可识别的 PubSub 时它也一并留空——与下面 PubSub 留空同理：
	// 连客户端类型都判不出来，退避策略的语义就无从选择，服务端不凭空捏造。
	switch ps := client.GetPubSub().(type) {
	case *pb.Settings_Publishing:
		out.BackoffPolicy = s.publishBackoffPolicy()
		out.PubSub = &pb.Settings_Publishing{Publishing: &pb.Publishing{
			// ...（本分支原有内容一行不动）
		}}
	case *pb.Settings_Subscription:
		out.BackoffPolicy = s.subscribeBackoffPolicy(ps.Subscription.GetGroup().GetName())
		fifo := false
		// ...（本分支原有内容一行不动，包括 fifo 那整段注释）
	}
```

**注意**：`ps.Subscription.GetGroup()` 返回的是 `*pb.Resource`，组名要再取一层 `.GetName()`。
