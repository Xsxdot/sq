# B7.2 发布打磨 v0.1.0 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让零上下文的陌生人能在 5 分钟内拿到 sq 并跑起来，且拿到的是合法可用、版本可追溯、控制台真能打开的二进制。

**Architecture:** 五个互不耦合的交付件（LICENSE / 模块路径 / 版本注入 / 部署件 / CI）+ 一次「先核对后重写」的文档改造。核对必须先于重写——否则重写只是把未被发现的陈旧记述重新排版，还盖一个「刚校对过」的章。

**Tech Stack:** Go 1.26.1（纯 Go 无 CGO）、Node（编 `web/dist`，版本此前无约束、本计划首次钉定）、GitHub Actions、systemd。

**Spec:** [docs/superpowers/specs/2026-08-19-release-polish-v0.1.0-design.md](../specs/2026-08-19-release-polish-v0.1.0-design.md)

## Global Constraints

- **模块路径**：全仓统一为 `github.com/Xsxdot/sq`（用户 08-19 确认仓库归属 `Xsxdot` 不改名不转账号）。
- **版本号**：`0.1.0`；git tag 形如 `v0.1.0`，去掉 `v` 前缀后即版本号。
- **许可证**：Apache-2.0，版权行 `Copyright 2026 Xsxdot`。
- **平台矩阵**：仅 `linux/amd64`、`linux/arm64`、`darwin/arm64`。**不出 windows、不出 386。**
- **Go 版本**：`1.26.1`（`go.mod` 的要求，CI 必须钉这个值或更高的补丁版）。
- **对外文档一律不出现内部里程碑编号**（M1–M7、v1.0、v1.1）——那是排期语言，对读者无意义。
- **禁止把 `web/dist` 的构建产物提交进仓库**。
- **禁止给 sq 加配置文件路径自动发现**（`--config` 为空时去找 `/etc/sq/sq.yaml`）——会改变现存部署的启动语义，属另立条目。
- **核对中若发现真缺陷，记录但不修**——本计划是校对不是修 bug；发现项写进 Task 6 的核对表，由审核者转 backlog。
- 日志一律用项目既有的 `slog`（`logger := slog.Default()`），**禁止 `fmt.Printf` 作为日志机制**。唯一例外见 Task 3 Step 3 的显式说明。

- [ ] **Step 1: 写失败的测试**

新建 `cmd/sq/version_test.go`：

```go
package main

import (
	"strings"
	"testing"
)

// 默认值必须让本地裸 go build 出来的二进制也能跑通 --version，
// 不能是空串——空串会打印出三行只有标签没有值的输出，看起来像坏了。
func TestVersionStringUsesDefaultsWhenNotInjected(t *testing.T) {
	got := versionString()
	for _, want := range []string{"sq dev", "commit: none", "built: unknown"} {
		if !strings.Contains(got, want) {
			t.Errorf("versionString() 缺少 %q，实际输出：\n%s", want, got)
		}
	}
}

// ldflags 注入后三个值都要如实出现。这里直接改包级变量模拟注入，
// 因为 -ldflags 的效果无法在单测里构造。
func TestVersionStringReflectsInjectedValues(t *testing.T) {
	oldV, oldC, oldD := version, commit, buildDate
	t.Cleanup(func() { version, commit, buildDate = oldV, oldC, oldD })

	version, commit, buildDate = "0.1.0", "abc1234", "2026-08-19T00:00:00Z"
	got := versionString()
	for _, want := range []string{"sq 0.1.0", "commit: abc1234", "built: 2026-08-19T00:00:00Z"} {
		if !strings.Contains(got, want) {
			t.Errorf("versionString() 缺少 %q，实际输出：\n%s", want, got)
		}
	}
}

// 输出必须以换行结尾——它直接喂给 fmt.Print，缺换行会和 shell 提示符黏在一起。
func TestVersionStringEndsWithNewline(t *testing.T) {
	if got := versionString(); !strings.HasSuffix(got, "\n") {
		t.Errorf("versionString() 未以换行结尾：%q", got)
	}
}
```

- [ ] **Step 3: 实现**

在 `cmd/sq/main.go` 的 import 块之后、`func main()` 之前加入：

```go
// 版本信息由构建期 -ldflags -X 注入，例如：
//
//	go build -ldflags "-X main.version=0.1.0 -X main.commit=$(git rev-parse --short HEAD) -X main.buildDate=$(date -u +%Y-%m-%dT%H:%M:%SZ)"
//
// 默认值刻意不是空串：本地裸 go build 不带 ldflags 也要能跑通 `sq --version`，
// 空串会打印出三行只有标签没有值的输出，看起来像功能坏了。
var (
	version   = "dev"
	commit    = "none"
	buildDate = "unknown"
)

// versionString 返回 `sq --version` 的完整输出（三行，末尾带换行）。
//
// 返回值直接喂给 fmt.Print，故必须自带结尾换行，否则会与 shell 提示符黏连。
// 单独抽成函数而非在调用点拼接，是为了让它可被单测断言——版本输出是用户
// 报 bug 时唯一的自证材料，格式变了要能当场发现。
func versionString() string {
	return fmt.Sprintf("sq %s\ncommit: %s\nbuilt: %s\n", version, commit, buildDate)
}
```

改 `run()` 的开头。**`flag.Parse()` 是既有的一行，不要新增第二次调用**——
只在它前面加一个 flag 声明，在它后面加一个分支。

改动前（`cmd/sq/main.go` 约 95–97 行，现状）：

```go
	cfgPath := flag.String("config", "", "配置文件路径（可选）")
	flag.Parse()
	cfg, err := config.Load(*cfgPath)
```

改动后：

```go
	cfgPath := flag.String("config", "", "配置文件路径（可选）")
	showVersion := flag.Bool("version", false, "打印版本信息后退出")
	flag.Parse()

	// --version 必须在配置加载之前处理：用户被要求「报一下你的版本」时，
	// 机器往往正处于配置写错、端口被占、数据目录不可写的状态——那正是
	// 需要问版本的场景。放到 config.Load 之后，恰好在最需要它的时候用不了。
	if *showVersion {
		fmt.Print(versionString())
		return nil
	}

	cfg, err := config.Load(*cfgPath)
```

`fmt` 与 `flag` 在 `cmd/sq/main.go` 均已导入（第 21–22 行），无需新增 import。

**关于 `fmt.Print`——这是本仓库唯一允许的例外，不要「修」成 logger：**
`--version` 的输出是**程序输出（stdout）**，不是日志。三条理由：
① 此处 `config.SetupSlog` 尚未执行，`slog.Default()` 还没按配置装配；
② 用户会 `sq --version | grep`，日志格式（带时间戳、level、key=value）会污染它；
③ 日志默认可能被配置成写文件或调高级别，那样 `--version` 会什么都不打印。

- [ ] **Step 1: 写 systemd 单元**

创建 `deploy/sq.service`：

```ini
# sq 消息队列的 systemd 单元。
#
# 职责：以专用系统用户托管单个 sq 进程，负责重启策略与停机超时。
# 边界：不负责安装、不负责建用户与目录（那是 install.sh 的事），
#       也不负责集群编排——多节点部署是各节点各跑一份本单元。
#
# 路径约定（与 install.sh 必须一致，改一处就要改两处）：
#   二进制 /usr/local/bin/sq   配置 /etc/sq/sq.yaml   数据 /var/lib/sq

[Unit]
Description=sq - RocketMQ 协议兼容的轻量消息队列
Documentation=https://github.com/Xsxdot/sq
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=sq
Group=sq
ExecStart=/usr/local/bin/sq --config /etc/sq/sq.yaml

# 工作目录兜住配置里 data_dir 漏写绝对路径的情况——sq 的默认值是
# 相对路径 ./data，工作目录不定死会写到意想不到的地方。
WorkingDirectory=/var/lib/sq

# 承重取值，别下调：sq 自身有 30s 的强制中断兜底（gracefulStopTimeout，
# cmd/sq/main.go），它按 ReceiveMessage 长轮询的服务端上限 20s 加余量取的。
# systemd 的停机超时必须比它宽裕，否则兜底还没跑完进程就被 SIGKILL，
# 在途 RPC 被硬切。45 = 30 + 15 余量。
TimeoutStopSec=45

# sq 正常停机退出码 0、启动失败退出码非 0，故 on-failure 不会因
# 正常 systemctl stop 而触发重启。
Restart=on-failure
RestartSec=5

# 常规加固。ReadWritePaths 只放开数据目录：配置目录对进程只读即可，
# sq 从不回写配置。
NoNewPrivileges=true
ProtectSystem=strict
ProtectHome=true
PrivateTmp=true
ReadWritePaths=/var/lib/sq

[Install]
WantedBy=multi-user.target
```

- [ ] **Step 2: 写安装脚本**

创建 `deploy/install.sh`：

```bash
#!/usr/bin/env bash
#
# sq 安装脚本。
#
# 职责：把发布包里的二进制、配置样例与 systemd 单元装到 FHS 约定位置，
#       建专用系统用户与数据目录。
# 边界：不 enable、不 start——装完只打印下一步命令让用户自己执行。
#       安装脚本擅自起服务是不礼貌的，且在编排系统里会与其调度打架。
#       也不负责升级配置格式：已存在的 /etc/sq/sq.yaml 一律不覆盖。
#
# 必须以 root 运行。同目录下需有 sq、sq.example.yaml、sq.service。

set -euo pipefail

BIN_DST=/usr/local/bin/sq
CFG_DIR=/etc/sq
CFG_DST="${CFG_DIR}/sq.yaml"
DATA_DIR=/var/lib/sq
UNIT_DST=/etc/systemd/system/sq.service
SQ_USER=sq

SRC_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"

log()  { printf '[install] %s\n' "$*"; }
fail() { printf '[install] 失败：%s\n' "$*" >&2; exit 1; }

log "开始安装 sq，来源目录 ${SRC_DIR}"

[[ ${EUID} -eq 0 ]] || fail "需要 root 权限（建用户、写 /usr/local/bin 与 /etc）"
command -v systemctl >/dev/null 2>&1 || fail "未找到 systemctl，本脚本只支持 systemd 系统"

for f in sq sq.example.yaml sq.service; do
  [[ -f "${SRC_DIR}/${f}" ]] || fail "发布包缺少 ${f}（期望在 ${SRC_DIR} 下）"
done

# 专用系统用户：--system 不建家目录、不可登录，降低被当作跳板的面。
if id -u "${SQ_USER}" >/dev/null 2>&1; then
  log "系统用户 ${SQ_USER} 已存在，跳过创建"
else
  useradd --system --no-create-home --shell /usr/sbin/nologin "${SQ_USER}" \
    || fail "创建系统用户 ${SQ_USER} 失败"
  log "已创建系统用户 ${SQ_USER}"
fi

install -d -m 0755 "${CFG_DIR}" || fail "创建 ${CFG_DIR} 失败"
install -d -m 0750 -o "${SQ_USER}" -g "${SQ_USER}" "${DATA_DIR}" || fail "创建 ${DATA_DIR} 失败"
log "目录就绪：${CFG_DIR}（配置）、${DATA_DIR}（数据，属主 ${SQ_USER}）"

install -m 0755 "${SRC_DIR}/sq" "${BIN_DST}" || fail "安装二进制到 ${BIN_DST} 失败"

# sq 发布流水线。
#
# 职责：从一个 v* tag 产出三平台发布包并建 GitHub Release。
# 边界：不跑测试（那是另一条线的事，本流水线假定被打 tag 的提交已经绿了），
#       不发 Docker 镜像（0.1.0 明确不做）。
#
# 两种触发：
#   - push tag v*        完整发布，产物挂到 Release
#   - workflow_dispatch  手工触发，只传 artifact 供下载核对，不建 Release
#     （本仓库零 CI 基础，这是第一个 workflow；调试轮次不该污染 Release 页）
name: release

on:
  push:
    tags:
      - 'v*'
  workflow_dispatch:

permissions:
  contents: write   # gh release create 需要

jobs:
  release:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0   # commit 短哈希需要完整历史

      - uses: actions/setup-node@v4
        with:
          node-version: '22'   # web/package.json 无 engines 字段，此处首次钉定

      - uses: actions/setup-go@v5
        with:
          go-version: '1.26.1'   # go.mod 的要求

      # 承重步骤，不可省略：web/dist 只有 .gitkeep 入库，
      # 用裸 go build 出的二进制控制台是空的，而 README 承诺
      # 「单二进制，启动即见一切」。这会是 0.1.0 最可能的首个 issue。
      # 前端是纯静态资源、与 GOARCH 无关，故只编一次、三平台共用。
      - name: 构建 Web 控制台
        run: |
          cd web
          npm ci
          npm run build
          test -f dist/index.html || { echo "::error::web/dist/index.html 缺失，前端构建未产出"; exit 1; }

      - name: 计算版本信息
        id: meta
        run: |
          if [ "${GITHUB_REF_TYPE}" = "tag" ]; then
            VERSION="${GITHUB_REF_NAME#v}"     # v0.1.0 -> 0.1.0
          else
            VERSION="0.0.0-dev+${GITHUB_SHA::7}"
          fi
          echo "version=${VERSION}"                                  >> "$GITHUB_OUTPUT"
          echo "commit=${GITHUB_SHA::7}"                             >> "$GITHUB_OUTPUT"
          echo "date=$(date -u +%Y-%m-%dT%H:%M:%SZ)"                 >> "$GITHUB_OUTPUT"
          echo "版本=${VERSION} commit=${GITHUB_SHA::7}"

      - name: 交叉编译三平台并打包
        env:
          VERSION: ${{ steps.meta.outputs.version }}
          COMMIT:  ${{ steps.meta.outputs.commit }}
          DATE:    ${{ steps.meta.outputs.date }}
        run: |
          set -euo pipefail
          mkdir -p dist
          LDFLAGS="-s -w -X main.version=${VERSION} -X main.commit=${COMMIT} -X main.buildDate=${DATE}"
          for target in linux/amd64 linux/arm64 darwin/arm64; do
            GOOS="${target%/*}"; GOARCH="${target#*/}"
            echo "=== 构建 ${GOOS}/${GOARCH} ==="
            stage="$(mktemp -d)"
            GOOS="${GOOS}" GOARCH="${GOARCH}" CGO_ENABLED=0 \
              go build -ldflags "${LDFLAGS}" -o "${stage}/sq" ./cmd/sq
            cp sq.example.yaml LICENSE README.md "${stage}/"
            cp deploy/sq.service deploy/install.sh "${stage}/"
            chmod +x "${stage}/install.sh"
            tar -czf "dist/sq_${VERSION}_${GOOS}_${GOARCH}.tar.gz" -C "${stage}" .
            rm -rf "${stage}"
          done
          cd dist && sha256sum *.tar.gz > SHA256SUMS
          echo "=== 产物 ==="; ls -lh; cat SHA256SUMS

      # 手工触发时只传 artifact，供下载核对，不碰 Release 页。
      - name: 上传 artifact（仅手工触发）
        if: github.event_name == 'workflow_dispatch'
        uses: actions/upload-artifact@v4
        with:
          name: sq-dist
          path: dist/

      - name: 建 Release（仅 tag 触发）
        if: github.ref_type == 'tag'
        env:
          GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
        run: |
          gh release create "${GITHUB_REF_NAME}" dist/* \
            --title "${GITHUB_REF_NAME}" \
            --generate-notes
```
